What this mockup proposes

  • New user menu, grouped: Planning (servings, meal times), Appearance (theme, Low FX), then Sign out and the version line.
  • Mobile: the menu becomes a bottom sheet over a scrim, with a close button, capped at the screen height and scrolling inside. Desktop keeps the anchored dropdown.
  • Theme applies instantly, is remembered on this device (fb.display.theme), defaults to Default.
  • Low FX row only appears while Cyberpunk is active.
  • The picker is a proper radiogroup: arrow keys move, 44px targets, focus ring in every theme.

Architecture (drives the plan rewrite)

  • Components read semantic tokens only (--surface, --ink, --accent…). Each theme is one [data-theme="…"] block on <html> plus one entry in a THEMES registry.
  • Default keeps today's look exactly; the reskin becomes the Cyberpunk block, so its colours no longer replace the current ones.
  • An inline script in index.html sets data-theme before first paint (no flash).

Open questions

  • Brand per theme: shown here as My Pantry Plan (Default) and FOODBYTES · Night Kitchen (Cyberpunk). OK?
  • Static assets (favicon, home-screen icon, manifest name) can't follow a per-device theme. Proposal: they stay on the Default brand; theme-color is updated live.
  • Pip's room stays on its own palette in every theme.
